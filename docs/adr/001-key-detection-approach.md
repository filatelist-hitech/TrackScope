# ADR 001: Real-time Key Detection Algorithm

## Status: Proposed

## Date: 2026-06-01

## Context

Нужен детектор тональности для live-аудио с микрофона (не файлов). Основные требования:
- Работает инкрементально на PCM-чанках (streaming, как DspEngine).
- Выдаёт Camelot-нотацию (`8A`, `8B` и т.д.) для гармонического микса.
- On-device, без сети.
- Не добавляет значимой CPU-нагрузки на горячий аудио-путь.
- Уместен для hitech-диапазона 155–230 BPM.

Рассматривались три варианта:

**A. HPCP + Krumhansl-Schmuckler (pure Rust DSP)**
- Harmonic Pitch Class Profile: 12-bin хроматический профиль из STFT-фреймов.
- Корреляция с 24 K-S профилями (12 мажор + 12 минор).
- Прецедент: Essentia, AcousticBrainz.

**B. Essentia C++ через FFI**
- Готовая реализация HPCP и chord detection.
- Добавляет ~10 МБ зависимость C++ в мобильный бандл.
- Усложняет кросс-компиляцию (Android NDK + iOS fat binary).

**C. TensorFlow Lite модель**
- Requires ML model (~5–20 МБ).
- Black-box: нет объяснимых кандидатов.
- TFLite delegate на ARM Neon — не гарантирован на всех Android.

## Decision

**Option A** — HPCP + Krumhansl-Schmuckler в чистом Rust.

Причины:
1. **Архитектурная согласованность**: DSP-ядро уже написано на Rust; добавление нового модуля следует той же границе (`core/dsp/src/key_analyzer.rs`).
2. **Нет внешних зависимостей**: не раздувает бандл, нет проблем с NDK/Podfile.
3. **Объяснимость**: HPCP-профиль и K-S корреляция — детерминированные, тестируемые синтетическими фикстурами.
4. **Интеграция с BpmSmoother**: Camelot-ключ стабилизируется в Dart так же, как BPM.
5. **Производительность**: FFT для HPCP (512 bin, 11 ms hop) — несколько мс на ARM; не конкурирует с onset-detection на горячем аудио-пути.

## Consequences

**Позитивные:**
- Нет дополнительных зависимостей в Cargo.toml.
- Тестируется теми же parity-инструментами (Python HPCP референс + Rust).
- `KeyResult` добавляется в `DspResult` как `Option<KeyResult>` — обратно совместимо.

**Ограничения:**
- Ожидаемая точность ~70–80% (hitech-материал: плотный бас маскирует хроматические составляющие).
- Latency ключа ~4–8 сек (нужно накопить достаточно HPCP-кадров).
- Для быстрых смен тональности (< 4 сек) ключ может не успеть обновиться.

**Риск плавного изменения тональности:** pitch-shift <2 полутона не детектируется изменением тональности — аналогично тому, как tempo jump detector не активируется при медленном изменении темпа.

## Implementation Notes

Файл: `core/dsp/src/key_analyzer.rs` (Phase 1 skeleton готов).
Тест-план: синтетические фикстуры с известной тональностью (чистые синусоиды по хроматическим ступеням), затем реальные hitech-фикстуры из `datasets/hitech/`.
