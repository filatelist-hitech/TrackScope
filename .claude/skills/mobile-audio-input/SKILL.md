# Мобильный аудио-вход

1. Запрашивать разрешение микрофона ДО открытия захвата. Документировать тайминг промпта на каждой платформе.
2. Захватывать моно-PCM-кадры callback-safe способом. Никогда не блокировать аудио-callback аллокацией, файловым I/O или сетью.
3. Передавать кадры в `core/ffi` (и через него в Rust DSP). Не считать BPM в Dart или в FFI-glue.
4. Рендерить только значения, возвращённые DSP-контрактом — `primary_bpm`, `confidence`, `lock_state`, `signal_quality`, `candidates`.
5. Отладочный экран обязан показывать: состояние захвата, уверенность, список кандидатов с relation, уровень входа в dBFS, флаг клиппинга и любые активные предупреждения.
6. Документировать на каждую платформу: частоту дискретизации, размер кадра, задержку callback, поведение разрешений, заметки про AGC. Держать `docs/MOBILE_AUDIO.md` в синхроне.
7. Конверсия частоты дискретизации: делать один раз, перед push'ем в DSP, с детерминированной политикой.

Жёсткие правила:

- Никаких демо-BPM, никаких случайных BPM, никакого фейкового пульса по таймеру — нигде в продакшен-пути.
- Не скрывать `CLIPPED_MIC`, `NOISE_ONLY`, `UNSTABLE` или низкую уверенность, чтобы UI выглядел стабильным.
- Никакой BPM-математики вне `core/dsp`.
