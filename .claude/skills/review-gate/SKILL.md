# Review-гейт

1. **Осмотреть diff** (staged + unstaged): `git status`, `git diff`, `git diff --staged`.
2. **Anti-fake**: подтвердить, что BPM вычисляется из аудио-/онсет-evidence или типизированных тестовых кандидатов — никогда не хардкод продакшен-значения, не случайные значения, не таймер-based.
3. **Уверенность + неопределённость**: подтвердить, что `confidence` рассчитан из evidence и неопределённость остаётся видимой (никакого автоматического `STABLE`).
4. **Сохранение кандидатов**: raw + half-time + double-time + нормализованные кандидаты — все присутствуют, с корректными `relation` и `source_bpm` для ловушек.
5. **Гейты состояния захвата**: тишина, белый/розовый шум, сильный клиппинг, брейкдаун не могут достичь `STABLE`.
6. **Границы**: BPM-математика живёт только в `core/dsp/`. `core/ffi/` и `apps/mobile/` — адаптеры.
7. **Тесты**: каждое изменение DSP-алгоритма добавляет или обновляет синтетическое покрытие. Ни один тест не ослаблен и не удалён.
8. **Parity**: там, где существуют parity-тесты Rust ↔ Python, они согласованы на изменённых фикстурах.
9. **Документация**: `docs/ARCHITECTURE.md`, `docs/DSP_ALGORITHM.md`, `docs/QA_MATRIX.md`, `docs/ROADMAP.md` отражают изменения, если релевантно.
10. **Прогнать валидацию**: `cargo test --workspace`, `python3 -m unittest discover core/tests`, `python3 tools/offline-lab/offline_lab.py report`, плюс `flutter test` / `flutter analyze`, когда тронут мобильный код.
11. **Отчитаться**: блокирующие проблемы (с file:line), не-блокирующие проблемы, отсутствующие тесты, тронутая документация, прогнанные команды, рекомендуемый следующий патч.
